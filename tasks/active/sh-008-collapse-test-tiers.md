# sh-008: Collapse the test tiers into one pixi-run harness, drop .venv

## Summary
The test-script layer carries complexity that only existed to support running
`test.sh` both inside and outside pixi and to catch a `.venv` drifting out of
sync with the `[dev]` extra. This task makes the pixi environment the only
supported way to run tests and tools: `test.sh` moves to `tools/run-tests.sh`,
the fast/full split collapses into a single `pixi run tests`, the `.venv` path
and its drift-detection machinery are deleted, and the README's `## Tests`
section is rewritten to describe intent rather than script internals. Both
former tiers ran in about a second, so the split earned nothing.

## Frontier Advice

STANDING OBLIGATIONS (`CLAUDE.md` § Standing task-planning obligations):
**Typed Python** is OPTED OUT with reason: this task deletes Python
(`tools/check_dev_extra.py`, `tests/test_check_dev_extra.py`,
`tests/test_harness_cli.py`) and adds none. Edits to surviving `.py` files
(`tools/check_lock_paths.py`, `tools/freecad_smoke.py`, `tools/layout_demo.py`)
are docstring/comment-only. The only `[tool.mypy]` change is dropping the
deleted `tools/check_dev_extra.py` from `files`. `mypy --strict` (run inside
`pixi run tests`) must still pass over the unchanged remaining sources.

WHY THIS IS SAFE. The fast/full split existed to let contributors without a
multi-GB FreeCAD install (and CI's cheap leg) run a subset. With pixi as the
only supported environment, everyone already has FreeCAD, so the subset has no
audience. The "core never imports FreeCAD" invariant it protected is enforced
independently by `shelving_core/tests/test_no_freecad.py` (textual scan +
`sys.modules` check), which stays in `pixi run tests`. Dropping the 3.11 CI leg
loses a version-matrix signal on a core that is pure stdlib plus `jsonschema`;
`requires-python = ">=3.11"` and ruff `target-version = "py311"` keep the source
3.11-compatible without a CI proof.

PIPELINE CONTRACT. Collapsing the tier split reaches past
`.claude/docs/pipeline.md`. `CLAUDE.md`'s meta-rule ("update `pipeline.md`
first, then grep `CLAUDE.md`, `.claude/agents/`, `.claude/skills/`, and
`docs/agent-usage.md` for one-line restatements to keep in sync") is mandatory
here. Sequence: (1) rewrite `pipeline.md` § Verification commands to one
command, and reword its "Who runs what" bullets, the two "both verification
tiers" phrase-table rows (`review`, `user_signoff`), and the Git-branching merge
line; (2) grep the locations above and reword each restatement tier-neutrally.
Change WORDING ONLY: not which agent runs checks at which phase, not the
rejection loop, not any phase transition. The "a live-infrastructure check
belongs in a durable automated test, not a one-off command" guidance
(`pipeline.md`, `reviewer.md`, `implementer.md`) stays, reworded to name
`pixi run tests` rather than a "full tier". `CLAUDE.md` itself has no fast/full
restatement to change (verified: it only carries the meta-rule). After editing,
`git grep -n 'fast tier\|full tier\|both tiers\|both verification tiers\|fast checks\|full checks'`
under `.claude/` and `docs/agent-usage.md` must be empty.

SINGLE-SCRIPT SHAPE. `tools/run-tests.sh` is a flat sequence under
`set -euo pipefail`, no functions beyond what readability needs, no argument
parsing except the no-arg guard. `set -e` makes "abort at first failure"
automatic; do not add manual `|| exit` chains except where a command's exit
status must be ignored (the `freecadcmd` smoke, per sh-007: its status is
meaningless, so `out="$(freecadcmd ... 2>&1)" || true` then grep the marker).
Resolve the repo root as
`cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd` (the script now lives one level
down in `tools/`).

DEPENDENCY MOVES. `pixi install` after editing `pixi.toml` regenerates
`pixi.lock`: expect churn from the two new conda packages on both platforms and
from `shelving-workbench`'s `requires_dist` losing the `dev` extra. Commit the
regenerated lock. Then run `python3 tools/check_lock_paths.py` against it and
confirm exit 0 (the self-install must read `- pypi: ./`, not an absolute path;
if it regressed, `rm pixi.lock && pixi lock` from a clean state rewrites it
relative, as in sh-005).

CI JOB. One job only. Do not keep a stub `fast` job. `pixi run tests` is the
whole CI test surface. `prefix-dev/setup-pixi` stays SHA-pinned with its
`# vX.Y.Z` comment and `frozen: true` (fail on a stale lock, never re-solve in
CI). `harden-runner` stays the first step. The no-`${{ github.event.* }}`-in-
`run:` rule and the rest of the top comment block are unchanged.

COORDINATION WITH sh-006 (currently `planning`, not started). sh-006 plans to
add `GITHUB_TOKEN` to the workflow-lint step of `ci.yml`, extend
`tools/lint-workflows.sh` with a `tools/check-action-pins.sh`, and it verifies
via `pixi run lint-workflows`. All three collide with this task (the single
`ci.yml` job, `lint-workflows.sh`, and the removed `lint-workflows` alias). This
is NOT a hard blocker (neither task imports the other's code). Whichever merges
second rebases; if sh-008 lands first, whoever re-plans sh-006 refreshes its
plan text. Do not edit `tasks/active/sh-006-*.md` from this task.

OUT OF SCOPE. The `.venv/` line in `.gitignore` stays (cheap insurance, not
"venv management"). No change to `requires-python` or ruff `target-version`. No
new pixi `[environments]`/`[feature]` tables (3.12-only means the default env is
the only env).

VERIFY WITH A GREP. The final step greps the whole repo (minus `tasks/`) for the
old interface: `test.sh`, `--fast`, `--full`, `.venv`, `[dev]`,
`pixi run fast|full|lint-workflows`, and tier words (`fast tier`, `full tier`,
`both tiers`). The only allowed survivor is `.gitignore`'s `.venv/` line.
`docs/roadmap.md`'s M0 entry is rewritten to describe what exists now
(`pixi run tests`). A stray hit fails the task.
