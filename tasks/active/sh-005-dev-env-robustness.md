# sh-005: Dev-environment robustness: editable pixi install, venv-drift preflight

## Summary
Two dev-environment papercuts from sh-003/sh-004: the pixi environment has no
editable `shelving_core` install, so every repo-root script needs a hand-copied
`sys.path` bootstrap; and `./test.sh --fast` fails at collection (rather than
with a clear message) when an existing `.venv` is missing a dependency newly
added to the `dev` extra. This task installs `shelving_core` editable into the
pixi env and adds a dev-extra check to the fast-tier preflight.

## Must Have
- [ ] `pixi.toml` installs the `shelving-workbench` project itself as an editable local package into the pixi environment (`[pypi-dependencies]` with `{ path = ".", editable = true }`, or the equivalent pixi manifest form), so `import shelving_core` works under `pixi run` / `pixi shell` with no per-script path shim. `pixi.lock` is regenerated by `pixi install` and still resolves for `linux-64` and `linux-aarch64`.
- [ ] `tools/layout_demo.py` no longer carries a `sys.path` bootstrap: the `_REPO_ROOT` computation and the `if _REPO_ROOT not in sys.path: sys.path.insert(...)` block are removed. Its module docstring states it must run inside an activated environment (`source .venv/bin/activate`, `pixi shell`, or via `pixi run`).
- [ ] `tools/freecad_smoke.py` is unchanged. Its bootstrap solves a different problem (importing `freecad.shelving` from the checkout under `freecadcmd`, whose bundled Python does not get pixi's editable install) and stays.
- [ ] `./test.sh --fast`'s `preflight_fast` gains a check: read the distribution names in `pyproject.toml`'s `[project.optional-dependencies].dev` (via `tomllib`, standard library) and confirm each is installed (`importlib.metadata.distribution(name)` succeeds). If one or more are missing, print `dev environment is out of sync with the [dev] extra: <names>. Run tools/install-deps.sh.` to stderr and exit 3 (same code as the missing-tool case). No network access.
- [ ] The dev-extra check runs before the existing tool checks or right after them, but always before `ruff`/`mypy`/`pytest` are invoked, so a stale env produces one clear message instead of a pytest collection error.
- [ ] `./test.sh --fast` exits 0 in a synced environment; `pixi run full` is green; `pixi run demo` and (from an activated `.venv`) `python tools/layout_demo.py` both exit 0; `tests/test_layout_demo.py` still passes without the removed bootstrap.
- [ ] `README.md` Setup or Tests section notes that repo-root scripts (`tools/layout_demo.py`) require an activated environment.
- [ ] Both `2026-08-31` friction-log entries (repo-root import bootstrap; test-only dep not reaching a provisioned `.venv`) are removed from `.claude/docs/friction-log.md`.
- [ ] `mypy --strict` and `ruff check .` / `ruff format --check .` clean. No new third-party dependency (the editable self-install is the project, not a dependency).

## Frontier Advice

STANDING OBLIGATIONS (`CLAUDE.md`): **Typed Python** applies. If the preflight
check is a `.py` helper it is fully typed; if it is an inline `python -c "..."`
inside `test.sh`, keep it minimal and correct (a short script reading
`tomllib.load` and iterating `importlib.metadata.distribution`). No other
standing obligation is active.

PIXI EDITABLE INSTALL: pixi supports a local editable package via
`[pypi-dependencies]` `shelving-workbench = { path = ".", editable = true }`.
Confirm the exact key against the installed pixi 0.78 (`pixi add --help` /
`pixi add --pypi --editable .` may be the ergonomic path). After editing the
manifest run `pixi install`, then `pixi run python -c "import shelving_core;
print(shelving_core.__file__)"` and confirm it points at the checkout, not a
copy. Commit the updated `pixi.lock`.

PREFLIGHT CHECK: distribution name is the PyPI/`pyproject` name, so
`importlib.metadata.distribution("jsonschema")` is the right call, not an
`import jsonschema`. This also works in the pixi (conda) env, where conda
registers dist metadata. Do not shell out to `pip`; `pip check` does not detect
a missing extra. Keep it network-free and fast.

`test.sh` STAYS AUTHORITATIVE for tier contents. The new check is part of the
`--fast` preflight only; `--full` inherits it because `--full` runs the full
`--fast` sequence. Exit code 3 stays reserved for "dev environment not ready"
(missing tool OR missing dev-extra dist); 2 for usage.

FRICTION LOG: this task resolves both `2026-08-31` entries; delete them in the
same commit that lands the fixes, per `.claude/docs/friction-log.md`'s protocol.
Record any NEW workaround per `CLAUDE.md`.
